### 結論
- **不需要串流載入（R-01）**：整張地圖一次載入仍有大幅餘裕。等地圖擴充到多個區域、數字接近預算一半時再重新評估。
- **B 級（M1 / Iris Xe 8 GB）尚未實測**：預估用低畫質。需要使用者提供 B 級機器量測（D-02）。

## Phase 6：近戰與魔法後（2026-10-13，M1 Pro）
`node scripts/perf.mjs --soak 15`（一般量測）與 `node scripts/perf.mjs --magic`（施法負擔）。

一般量測（不限幀，每幀 ms）：低 2.6–3.5、中 3.7–5.3、高 4.0–5.0；draw calls 最多 257（高）、221（低）；三角面最多 49 萬。比 6B 多約 0.4–0.8 ms（中高畫質常駐 2 盞點光源、武器模型、HUD），仍有 3 倍以上餘裕。中畫質 vsync 欄有幾個視角低於 120（101–115），與這次量測時背景負載有關（不限幀欄正常）；B 級機器量測時再確認。

施法負擔（森林、迷霧生物在場；每 0.25 秒同時按 Q 與 F、星光補滿，連續 6 秒）：

| 畫質 | 站著：每幀 ms | 施法中：每幀 ms（平均 / 最差取樣） | draw calls 站著 → 施法中最大 | 活著的粒子最大 / 容量 |
|---|---|---|---|---|
| 低 | 2.7 | 2.9 / 3.0 | 187 → 189 | 416 / 800 |
| 中 | 4.5 | 4.8 / 4.9 | 215 → 221 | 338 / 2000 |
| 高 | 4.5 | 4.8 / 5.0 | 226 → 228 | 312 / 3000 |

- 施法只增加約 0.3 ms：粒子全部在 GPU 計算、一個 draw call；魔法陣、衝擊波、點光源都是固定數量的物件池。施法時 draw calls 最多增加 6（魔法陣、衝擊波、拖尾）。
- 第一次量測時中畫質施法的最差取樣是 35.9 ms：魔法陣與衝擊波的 shader 在第一次出現時才編譯。改為載入後前 3 幀以全透明畫一次（近戰的拖尾與命中特效同樣處理），卡頓消失。
- 低畫質不放點光源（GAME_DESIGN 6.2：B 級機器優先）。
- 粒子上限遠高於實際用量（同時最多約 400 顆），預算足夠 6E 的流星雨。

## Phase 6：流星雨後（2026-10-13，M1 Pro）— 量測環境受干擾，待重測
`node scripts/perf.mjs --magic`（加入流星雨；每 0.25 秒清除冷卻後同時按 Q、F、C，最壞情況）兩次：

| 畫質 | 站著：每幀 ms | 施法中：每幀 ms（平均 / 最差取樣） | draw calls 站著 → 施法中最大 | 活著的粒子最大 / 容量 |
|---|---|---|---|---|
| 低 | 5.2 / 5.3 | 5.4 / 5.9；5.4 / 6.1 | 187 → 195 | 98 / 800 |
| 中 | 11.1 / 10.0 | 11.0 / 11.7；11.7 / 28.9 | 214 → 225 | 261 / 2000 |
| 高 | 10.7 / 10.2 | 11.8 / 19.3；10.9 / 20.2 | 223 → 233 | 247 / 3000 |

- **這兩次與同時段的一般量測（低畫質跟隨角色 3.5 → 5.2 ms、高畫質 4.9 → 8.0 ms）都比稍早慢約 1.6 倍，包含沒有點光源的低畫質**；量測時偵測到 Chrome 與活動監視器正在執行（CLAUDE.md：量測時不要操作電腦）。程式碼在這段期間只加入了流星雨（閒置時沒有額外計算），判斷是環境因素，**需在無人操作時重新執行 `node scripts/perf.mjs --magic` 與 `node scripts/perf.mjs` 確認**。
- 同一次執行內的相對比較仍有效：施法（含連續好幾波流星雨）平均只增加 0.1–1.7 ms，draw calls 最多 +10，粒子同時最多約 260 顆，遠低於預算。最差取樣（20–29 ms）出現在同時有多波流星光爆時，且受環境干擾；正常遊玩流星雨 30 秒冷卻，不會連續發生。
